# AIFlow 1.0e 고도화 구현·실측

상태: 현재 자료로 가능한 구현·예정 비교·두 seed 재현 검사를 완료했다. 자료·권리가 필요한 의존 단계는 아래와 같이 차단한다. 점수는 신규 독립 평가가 아닌 기존 7명·95수식·387문자의 개발 진단이다.

결론: 기준 종단간 Exact 14/95(14.74%)에서 기본 seed 후보 32/95(33.68%)로 개선. 추가 seed는 31/95·30/95이며 세 seed 평균은 32.63%다. 동일한 95개 수식을 반복한 결과이지 독립 표본 285개가 아니다. 연구 가중치와 재현 자료까지만 완료했으며 상용 승격·제품 후보 패키지는 보류한다.

- head의 27→31은 저장된 예측 기호·구조의 결정적 재직렬화 결과다. 새 가중치 효과로 계산하지 않는다. 이후 joint 실행에서는 원본 획으로 실제 재추론하여 top-1 31개도 다시 확인했다.
- `\\times` 뒤 Latin 문자가 붙어 다른 제어어로 해석되는 오류를 구분 공백으로 수정했다. 기호, 수학적 정답, 정답 구조를 바꾸지 않는다.
- head+joint는 직전 head top-1 대비 개선 2개·회귀 1개, 획 묶음 전체 정답 76→86개다. 처음 외부 HWR 기준 대비 개선 20개·회귀 2개다. 제품 무회귀를 주장하지 않는다.
- MLP A의 raw E2E는 기준 대비 개선 14개·회귀 8개다. guarded E2E는 19/95이며 개선 6개·회귀 1개로, guard도 신규 writer 무회귀를 보장하지 않는다.
- MLP B는 raw 기준 개선 9개·회귀 9개다. guarded E2E는 19/95로 개선 5개·수식 회귀 0개이며, 정답 묶음 제공 문자 진단도 233/387·문자 회귀 0개다. 위치 복원만으로 raw 정확도가 향상된 것은 아니며 이 부정적 결과도 보존한다.
- MLP C도 raw 14/95이고 guarded는 18/95·수식 회귀 1개다. KL 수학적 오류 수정과 실측 정확도 향상을 구분한다.
- 마지막 block의 joint E2E와 구조 Exact는 head와 같다. 정답 묶음 제공 문자 점수는 279 대 276으로 조금 높다. 다른 예정 비교가 이를 넘지 않아 계획의 우선순위에 따라 마지막 block 구성을 재현 검사 대상으로 고정했다.
- 선택한 마지막 block joint의 기준 대비 개선은 21수식·회귀 3수식이다. Exact 차이 +18.95%p의 writer bootstrap 10,000회 구간은 +10.19~+28.10%p다. **소비된 개발 자료의 진단 구간이며 독립 승격 검증이 아니다.**
- CE/KD의 가중치는 실제 학습했으나 이번 설정에서 정확도 이득이 없었다. 모델 구현 성공을 성능 개선으로 표현하지 않는다.
- 기존 v4/teacher/student의 81.91~90.70% 문자 점수는 별도 `legacy_development`로 보존한다. 같은 encoder·같은 평가 경계가 아니므로 새 수치와 단순 전후 비교하지 않는다.

## 구현과 검증 경계

- 7 outer writer-LOO, 각 outer 내부 writer 3-fold. 실제 fit/selection ID와 산출물 SHA를 부모 그래프로 검증.
- 평가 writer뿐 아니라 같은 수식 표기의 학습 유입도 차단. teacher target 생성·정규화·student·guard의 제외 경계를 유지.
- 외부 HWR 사전학습 전체 원자료를 새로 감사한 것은 아니다. 기존 external-only 학습 보고서와 데이터 카탈로그에 근거한 시작 가중치다.
- 원본 위치 복원, 위치 결측 마스크, 후보 축 KL 합산, 수식 평균 손실, padding·후보 누락 보존, residual 초기 동등성 구현.
- online-only 공동 추론, 모든 획 exact-cover, 단일점·지연 획 보존, 완료 이벤트 멱등성 및 오류 시 raw ink 복원 구현.
- 이미지 teacher import와 소켓 연결을 차단한 실제 CPU 추론 검사 통과. 이는 실제 휴대기기·제품 패키지 검증의 대체가 아니다.
- 코드와 체크포인트의 기록 SHA를 보존했다. 일부 초기 joint 실행은 source SHA만 있고 전체 소스 복사본이 없어 완전한 실행 소스 아카이브라고 주장하지 않는다.

## 후보 상한 진단

head의 고정 Top-5·정답 문자 묶음에서는 정답 후보를 완벽하게 선택하더라도 47/95(49.47%)가 상한이다. 48개 수식은 정답 후보가 하나 이상 빠져 있다.

후보 안의 오답을 독립 확률 q로 수정하고 새 오류를 만들지 않는다는 가정에서는 `(33 + 13q + q²)/95`이다. q=0.25/0.5/0.75에서 38.22/41.84/45.59%다. **종단간 Exact나 달성 예측이 아니다.**

같은 head의 전체 logits를 고정한 K 비교도 완료했다.

| K | 문자 후보 포함률 | 정답 묶음 제공 oracle | 실제 joint E2E |
|---:|---:|---:|---:|
| 5 | 326/387 (84.24%) | 47/95 | 32/95 |
| 10 | 330/387 (85.27%) | 49/95 | 32/95 |
| 20 | 333/387 (86.05%) | 50/95 | 32/95 |

수식 Exact가 같으므로 이 head 비교에서는 K=5를 유지한다. 후보 포함률 상승만으로 제품 정확도 상승을 주장하지 않는다.

외부 기반 HWR를 고정한 시간 입력 비교는 uniform-time 14/95, preserve 13/95다. fine-tuned head의 시간별 재학습 비교는 아니며, 이 진단만으로 실제 시간 특징이 일반적으로 불필요하다고 결론 내리지 않는다.

### 확인된 후보 누락 병목

- 고정 어휘 372개 중 `=`는 index 371에 있다. 그러나 승인 외부 replay `math_train` 167,088행에서 `=` 예제는 **0개**다. 나머지 371개 클래스는 예제가 있다.
- 비교 가능한 유사 기호의 외부 예제는 `\\approx` 1,836개, `\\simeq` 792개다. 이 기호들을 `=`로 합치거나 출력 후 치환하지 않았다.
- head Top-5 누락 61문자 중 `=` 42개, `8` 7개다. `=`→`\\simeq` 10개와 `=`→`\\approx` 5개가 실제 오답에 포함된다.
- 현재 자체 자료로 head를 미세조정한 사실과 외부 replay의 해당 클래스 부재를 구분해야 한다. 외부 기반 기준선의 낮은 점수를 평가 누수 수정 하나의 효과라고 단정하지 않는다.
- 다음 자료 보강에서는 권리가 확인된 `=`·숫자·유사 기호의 writer-disjoint 예제를 우선 확보한다. 이 발견을 이용한 평가셋 전용 치환·정답 후보 삽입은 금지한다.
- 근거: `artifacts/unified_head_20260813/unified_math_8ep_full/cache/cache_manifest.json` 및 해당 `math_train` labels 배열, `accuracy_upgrade_20260911_r4_hwr_head/glyph_predictions.jsonl.gz`.
