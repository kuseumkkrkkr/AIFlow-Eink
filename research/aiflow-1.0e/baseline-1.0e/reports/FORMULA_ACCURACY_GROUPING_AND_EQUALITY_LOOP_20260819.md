# 공식 정확도: ownership 교정과 직선 등호 복원 루프

## 결론

- 잘못 묶인 project-owned stroke ownership 3식을 교정한 뒤 기존 모델과 전체 후단을 그대로 재생했다.
- 고정 분모 387글자·95식에서 최종 공식 배치 출력은 `362/387 → 369/387`, 식 완전일치는 `81/95 → 84/95`로 상승했다.
- 후단에 직선 2획 등호 보존 gate를 추가하면 `371/387`(95.87%), `85/95`(89.47%)가 된다.
- 기존 최종 출력 대비 문자 회귀 0, 식 회귀 0이다. CROHME 반복 진단도 `7516/9535`, `288/984`로 변하지 않았다.
- 이번 루프에서는 학습하지 않았다. ownership 교정은 데이터 품질 수정이고, 등호 gate는 후보 보존형 shadow 레이어다.
- `85/95`는 검수된 문자 ownership이 입력된 box-local 식 문자열 완전일치다. 원시 stroke의 자동 문자 분할까지 포함한 end-to-end 수치가 아니다.

## 직선 등호 슬롯 gate

현재 식에 `=`가 없고 숫자 사이의 한 슬롯만 다음 조건을 모두 만족할 때 Top-20 안의 `=`를 선택한다.

- `=` rank 3 이내, 확률 0.1 이상
- 2 strokes, `aspect_log ≥ 0.8`
- `path_over_diag ≤ 1.2`, `|direction_y| ≤ 0.2`
- 한 식에서 최대 1글자

직접 데이터에서는 `aiflow_0018`의 `≈→=`로 식 1개가 완전히 복원되고, `aiflow_0023`의 `1→=`로 글자 1개가 추가 복원된다. 산술식의 참·거짓은 계산하지 않는다. CROHME에는 조건을 만족하는 적용 사례가 0건이었다.

## 잔여 10식 시각 중검수

원본 ordered strokes, ownership 전체 식, 오답 glyph 정규화 그림을 함께 렌더링해 10식을 다시 확인했다. 추가 ownership 경계 오류나 결측 그룹은 없었다.

| 구분 | 식 | 판정 |
|---|---|---|
| 문법만으로 구별 불가한 동형군 | `0010`, `0061`, `0078`, `0146` | `x/X/χ`, `β/8`, `S/5`; 신규 식 문맥 자료 필요 |
| 여러 저확률 HWR 오류 동시 발생 | `0020`, `0056`, `0058` | 한 식에서 3글자씩 강제하면 회귀 위험이 큼 |

`0004`의 2획 교차를 `+`로 바꾸는 probe는 직접 1식 개선·CROHME 적용 0건이었다. 그러나 정상 숫자 `247`을 훼손할 수 있고 독립 반례가 없으므로 런타임에 채택하지 않았다. 남은 식에 대한 추가 규칙 보정은 여기서 중지한다.

## 남은 경계

- 최종 실패는 10/95식이다. 그중 9식은 정답이 Top-20에 있으나 `x/X/χ`, `β/8`, `S/5` 또는 여러 저확률 글자를 동시에 바꿔야 해 현재 데이터만으로 안전하게 확정할 수 없다.
- 직접 95식은 반복 개발 자료이고 CROHME는 비상업 반복 진단 자료다.
- 직선 등호 gate도 독립 양성 사례가 없으므로 제품 기본값은 꺼져 있다. 신규 작성자·신규 식의 상업 사용 가능한 untouched acceptance가 필요하다.
