# Top-20 짝 없는 괄호 피연산자 배치 복원 루프

## 결론

- 수식 배치 레이어에 구조적으로 불가능한 닫는 괄호 한 종류를 처리하는 shadow 분기를 추가했다.
- 직접 수집 개발 95식의 완전일치는 `78/95`에서 `79/95`(83.16%)로, 문자 Top-1은 `358/387`에서 `359/387`(92.76%)로 증가했다.
- CROHME 반복 비상업 진단 984식·9,535문자에서는 변경 0건, 회귀 0건이다.
- 수정은 `aiflow_0142`의 `5 \times ) = 5`를 `5 \times 1 = 5`로 복원한 한 건뿐이다.
- 제품 기본값은 변경하지 않았다. 현재 상태는 `shadow_runtime_only`다.

## 배치 위치

```text
128점 온라인 궤적
  -> 372-class HWR와 보조 HWR
  -> 수식 문맥·배치·구문 복원
  -> 연구용 Top-20 후보 회수
  -> 짝 없는 닫는 괄호 피연산자 가드
  -> 기존 식 순서·관계 그래프 유지
```

문자 삽입·삭제, 순서 변경, stroke regrouping, 관계 그래프 변경, 산술 계산은 수행하지 않는다.

| CROHME 반복 비상업 진단 | 9196/9535 | 9340/9535 | 773/984 | 851/984 |

두 범위 모두 Top-20의 앞 10개 토큰과 확률은 기존 Top-10 캐시와 완전히 같았다. 새로 직접 회수된 식은 `2+7`, `10+8`, `5×1=5` 세 개지만 앞의 두 식은 문법·배치만으로 유일하게 확정할 근거가 부족해 보존했다.

## 기각한 경로

고정 문맥 신경망으로 Top-20 전체를 재정렬하면 직접 수집 식 exact가 `78/95 → 60/95`로 내려가고 18식이 회귀했다. 이 분기는 기각했다.

숫자 후보 확률 하한을 `0.000001`까지 낮추면 직접 수집은 `79/95`가 되지만 CROHME는 `288/984 → 284/984`, 문자 회귀 9건, 식 회귀 4건이 발생했다. 특히 올바른 `\sqrt{}`를 숫자로 바꾸므로 확률 하한 완화도 기각했다.

## 채택한 구조 가드

다음 조건을 모두 만족할 때만 현재 닫는 괄호를 후보 안의 `1`로 바꾼다.

- 현재 HWR 1위와 후보 앞 5개가 모두 닫는 괄호 계열이다.
- 같은 식의 앞쪽에 대응하는 여는 괄호가 없다.
- 해당 위치의 바로 앞은 이항 연산자, 바로 뒤는 관계 기호다.
- 기존 식에 숫자가 이미 두 개 이상 있고, 교체 후 숫자 구문이 유효하다.
- Top-20의 숫자 후보가 `1` 하나뿐이다.
- 한 stroke이고, 세로 방향 절댓값 0.9 이상, `aspect_log <= -1.5`, `path/diagonal <= 1.15`, 상대 폭 0.08 이하인 거의 직선 궤적이다.
- 한 식에 가능한 복원 위치가 정확히 하나뿐이다.

정답 문자를 직접 읽거나 산술 결과를 계산하는 조건은 없다. 다만 이 경계는 반복 관찰한 직접 수집 자료에서 만들어졌으므로 독립 검증 전에는 상용 기본값이 아니다.
