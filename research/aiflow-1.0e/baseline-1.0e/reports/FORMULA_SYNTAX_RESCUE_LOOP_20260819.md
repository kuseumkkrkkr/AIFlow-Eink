# 수식 구문 복원 개선 루프

## 결론

- 공식 배치 뒤에 후보 보존형 `formula_syntax_rescue_v1`을 연결했다.
- 직접 수집 95식 완전일치는 69식에서 72식으로 증가했고 회귀는 0식이다.
- 최신 공식 배치 기준 CROHME 비상업 진단은 283식에서 284식으로 증가했고 회귀는 0식이다.
- 관계 그래프는 그대로 유지되며 관계·문자 동시 완전일치는 225/984에서 226/984로 증가했다.
- 현재 상태는 `shadow_runtime_only`다. 직접 수집식은 반복 개발에 사용됐고 CROHME는 비상업·반복 진단셋이므로 상용 승인 표본이 아니다.

## 고정 구조

```text
온라인 stroke
  → 372-class HWR Top-5
  → 프로젝트 소유 Transformer 문맥 확정
  → 공식 배치·관계 그래프
  → 한 글자 수식 구문 복원
  → 후보 보존 수식 그래프·shadow LaTeX
```

구문 복원은 다음 조건을 모두 만족할 때만 동작한다.

앞 단계의 `formula_sequence_guard_v1`이 문자를 바꾼 경우에는 변경된 수식열로 MASK 문맥 점수를 다시 계산한 뒤 구문 복원을 평가한다. syntax config만 단독으로 켜도 sequence guard가 암묵 실행되지는 않는다.

- `+`·등호 복원은 현재 수식열과 변경 후 수식열이 모두 단순 숫자 구문으로 유효해야 한다.
- 한 식에서 최대 한 글자만 바꾼다.
- 바꿀 문자는 해당 글자의 고정 HWR Top-5 안에 있어야 한다.
- `숫자·숫자·숫자` 3항식의 가운데 `+` 후보, 또는 HWR 1순위와 선택 후보가 모두 등호 계열인 경우만 허용한다.
- `/→-`는 식 내부 글자이면서 `aspect_log≥0.5`, 절대 진행 기울기 `≤0.6`인 강한 수평 stroke에만 허용한다.
- 후보 확률비는 0.0005 이상, 최종 점수 차는 0.5 이상이어야 한다.
- 산술의 참·거짓을 계산하지 않고 새 token·삭제·stroke ownership 변경을 금지한다.

직접 수집 실제 변경은 세 건이다.

- 직접 `aiflow_0128`: `12-0112` → `12-0=12`
- 직접 `aiflow_0005`: `544` → `5+4`
- 직접 `aiflow_0123`: `5/0` → `5-0`

CROHME에서는 다음 두 글자가 개선됐고 회귀는 없다.

- CROHME `513_em_310.inkml`: `847` → `8+7`
- CROHME `RIT_2014_178.inkml`: 수평형 `/` → `-` 한 글자

가로선 감사에서 직접 수집 eligible 2건 중 실제 `-` 1건만 선택하고 `/` 1건은 유지했다. CROHME eligible 7건에서도 실제 `-` 1건만 선택하고 `/` 5건·`\prime` 1건은 유지했다.

128/256 추론 배치 크기 비교에서 최종 문자 차이는 0건이었다. 이전 CROHME 런타임과의 차이는 배치 비결정성이 아니라 앞 루프에서 추가한 괄호 포함 루트 관계가 문맥 순서를 갱신한 결과였다. 이 보고서의 OFF/ON 수치는 모두 최신 배치 코드로 다시 생성한 통제 비교다.

## 기각 분기와 상한

- 모든 유효 숫자열에 누락 구조를 허용한 넓은 정책은 직접 수집 2식을 고쳤지만 CROHME에서 1식·3글자 회귀가 발생해 기각했다.
- 계산 결과가 맞도록 등식이나 연산자를 강제하는 방식은 사용자가 틀리게 쓴 답을 바꿀 수 있어 제품 경로에서 금지했다.
- 직접 수집 Top-5 수식 oracle은 77/95다. 현재 72/95 이후 남은 23개 실패식 중 최소 18식은 정답 문자가 Top-5 밖에 있어 문맥 후단만으로 해결할 수 없다. 다음 큰 개선은 HWR 후보 recall과 신규 상용 소유 수식 데이터에서 나와야 한다.
